    1. Einführung

    Das PDF des Dokuments finden Sie HIER.

    Den Code des Dokuments finden Sie HIER.

    Dieses Dokument ist ein Produkt der KI Claude von Anthropic. Es knüpft an den Kurs „Schritt-für-Schritt-Einführung in das Web-Framework NestJS“ an, wechselt aber die Perspektive:

    • Im Kurs [NestJS] erzeugt der Server die HTML-Seiten (View-Engine [Handlebars]); der Browser zeigt sie lediglich an;
    • in diesem Kurs werden die Seiten im Browser von einer Anwendung [Angular] erzeugt; der Server, nun auf einen einfachen JSON-Server reduziert, liefert nur noch Daten.

    Die Seiten der Anwendung bleiben jedoch unverändert: Es sind die der Anwendung [RdvMedecins], die bereits mit den anderen Frameworks vorgestellt wurde (Anmeldung mit CAPTCHA, Terminkalender des Arztes, Terminfenster, Patientenportal, Arzt- und Clientverwaltung, Kontoerstellung, Französisch und Englisch).

    Dieses Dokument folgt demselben Aufbau wie seine Vorgänger: zunächst zahlreiche kurze Beispiele, die jeweils ein bestimmtes Konzept von [Angular] behandeln, gefolgt von einer vollständigen Fallstudie – dem [Angular]-Client der Anwendung [RdvMedecins] – mit kommentierten Dateien. Es folgt der Gliederung des Kurses „Schritt-für-Schritt-Einführung in das Framework Vue.js“: Leser, die mit [Vue.js] vertraut sind, finden dieselben Beispiele im Stil von [Angular]. Da [Angular] ein funktionsreicheres Framework ist, gibt es mehr Beispiele: 25 statt 20.

    Zu diesem Thema gibt es bereits einen Kurs: Ein Client-Server-Beispiel - Angular / NestJS (2026), der sowohl den Server als auch den Client behandelt. Dieses Dokument unterscheidet sich in seinem Ansatz: Der Server wird als Blackbox behandelt, wobei uns nur die API und das JSON interessieren, und wir lernen [Angular] Schritt für Schritt, bevor wir den vollständigen Client in Angriff nehmen.

    1.1. Die Rolle von Angular in einer Webanwendung

    Die Anwendung besteht aus zwei Teilen, die nur über Anfragen miteinander kommunizieren:

    • 1: Die Anwendung [Angular] sendet im Browser eine HTTP-Anfrage an den Server, zum Beispiel [GET /api/schedule?doctorId=1&day=2026-10-05];
    • 2: Der Server antwortet mit JSON-Daten: dem Terminkalender dieses Arztes für diesen Tag. Er erzeugt keine Seiten;
    • 3: Anhand dieser Daten aktualisiert [Angular] die im Browser angezeigte Seite, ohne sie neu zu laden.

    Das folgende Diagramm vergleicht die beiden Architekturen:

    Der Browser lädt beim Start nur eine einzige, fast leere HTML-Seite. Alles Weitere wird von [JavaScript]-Code erzeugt: Man spricht von einer Single-Page-Anwendung (SPA, für [Single Page Application]). Wenn der Benutzer auf einen internen Link klickt, wird keine Seite vom Server angefordert: Der [Angular]-Router ändert die angezeigte URL und ersetzt den Inhalt der Seite.

    [Angular] ist ein von Google entwickeltes Framework. Seine erste Version, [AngularJS] (2010), wurde 2016 vollständig neu geschrieben: Diese Neuentwicklung in [TypeScript] wird heute einfach [Angular] genannt und veröffentlicht alle sechs Monate eine neue Hauptversion. Es beruht auf drei Ideen:

    • Komponenten: Die Oberfläche wird in wiederverwendbare Bausteine zerlegt (eine Navigationsleiste, ein Formularfeld, ein Bestätigungsfenster usw.). Eine Komponente ist eine [TypeScript]-Klasse, der ein HTML-Template und ein CSS-Stil zugeordnet sind;
    • Reaktivität, basierend auf Signals: Die Daten einer Komponente werden in Signals gespeichert. Ändert sich eines davon, aktualisiert [Angular] automatisch die Teile der Seite, die es anzeigen. Wir schreiben nie Code, der die Seite direkt verändert;
    • Dependency Injection: Komponenten erzeugen die Objekte, die sie benötigen (Serverzugriff, angemeldeter Benutzer, Sprache usw.), nicht selbst; sie fordern sie an, und [Angular] stellt sie bereit. Dies ist der Mechanismus, den der Kurs [NestJS] bereits auf der Serverseite vorgestellt hat – [NestJS] wurde tatsächlich davon inspiriert.

    Anders als [Vue.js] ist [Angular] ein „All-in-one“-Framework: Router, Formulare, HTTP-Client, Animationen und Tests werden vom [Angular]-Team selbst bereitgestellt, zusammen mit Empfehlungen für die Verwendung.

    Wir verwenden [Angular] 22 mit seinen neuesten Funktionen: Standalone-Komponenten ([standalone]), Signals, die neue Template-Syntax ([@if], [@for]), signalbasierte Formulare und Change Detection ohne [zone.js] ([zoneless]), was in [Angular] 22 das Standardverhalten ist.

    1.2. Verwendete Werkzeuge

    Die Beispiele wurden mit den folgenden Werkzeugen geschrieben und getestet (ihre Installation wird im Anhang beschrieben):

    • [Node.js] 24 (oder mindestens 22.22.3: Das ist die Voraussetzung für [Angular] 22) und sein Paketmanager [npm];
    • der Editor [Visual Studio Code] mit der Erweiterung [Angular Language Service];
    • ein aktueller Browser ([Chrome], [Firefox], [Edge]), wenn möglich mit der Erweiterung [Angular DevTools];
    • das Kommandozeilenwerkzeug [curl], das die rohen HTTP-Antworten anzeigt;
    • das DBMS [MySQL] (oder [MariaDB]), zum Beispiel das von [Laragon] unter [Windows]: Es wird für den JSON-Server benötigt, wie im Kapitel zu seiner Vorstellung beschrieben.

    Die Bibliotheken sind die der Dateien [package.json]: [Angular] 22.2 (der Kern, der Router, die Formulare, der HTTP-Client), das Kommandozeilenwerkzeug [Angular CLI] (Befehl [ng]), [RxJS] 7.8 (Observables), [ngx-translate] 18 (Sprachen), [TypeScript] 6.0, [Bootstrap] 5.3.

    Installieren Sie die Bibliotheken einmalig in einer Konsole, die im Ordner [examples-angular] geöffnet ist (in [VS Code]: Menü Terminal / Neues Terminal):

    npm install

    Starten Sie dann ein Beispiel, indem Sie seinen Namen eingeben:

    npm start 01-first-application

    Der [Angular]-Entwicklungsserver kompiliert das Beispiel und stellt es auf Port 4200 bereit: Öffnen Sie es unter http://localhost:4200/. Dieser Server muss nicht neu gestartet werden, wenn Sie eine Datei ändern: Jede gespeicherte Datei wird sofort neu kompiliert, und die Browserseite aktualisiert sich automatisch. Beenden Sie ihn in der Konsole mit [Ctrl-C] , bevor Sie das nächste Beispiel starten (nur ein Beispiel gleichzeitig kann Port 4200 belegen).

    Die Beispiele 22 bis 25 fragen den JSON-Server [RdvMedecins] ab: Sie müssen ihn installiert haben und ausführen, wie im ihm gewidmeten Kapitel erläutert.
